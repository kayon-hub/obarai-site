要用什麼瀏覽器開啟ORBIT？

全部

網址：app.obarai.com

  1. 第一次使用：iPhone 請用「Safari」開啟，Android 請用「Chrome」開啟。
  2. 開啟後先登入，再把圖示加到手機桌面（見下方條目）。
  3. 之後每次使用，一律點手機桌面的 ORBIT 圖示進入，不要再從瀏覽器網址列或書籤開。
  4. 不要從 LINE、Facebook、Instagram 等 App 內建的小瀏覽器直接點連結開啟——這種內建瀏覽器抓不到定位（打卡需要用），部分手勢操作（例如滑動打卡）也可能沒反應。

電腦（Windows/Mac）上使用不限瀏覽器種類，Chrome、Edge、Safari 都可以，只有手機的「LINE 內建瀏覽器」明確不能用。判斷方法：畫面若出現 LINE 自己的工具列（例如右上角三個點選單、「用預設瀏覽器開啟」選項），就代表是 LINE 內建瀏覽器，請改用桌面圖示開啟。

如何把ORBIT加到手機桌面(iPhone)？

全部
  1. 用「Safari」開啟 app.obarai.com（如果是從 LINE 點連結進來的，請先按住連結選「複製連結」，再貼到 Safari 網址列開啟，不要直接在 LINE 裡點開）。
  2. 點畫面下方（或上方，依 iOS 版本而定）的「分享」按鈕（方形+向上箭頭圖示）。
  3. 往下滑選單，點「加入主畫面」。
  4. 右上角點「新增」。
  5. 之後桌面上會出現 ORBIT 的圖示，名稱顯示為「ERP.POS」，之後一律點這個圖示進入系統。

一定要用 Safari：用 Chrome、LINE 內建瀏覽器等其他方式加入主畫面，可能不是完整的獨立 App 模式，定位功能也可能不正常。桌面圖示名稱顯示「ERP.POS」，不是「ORBIT」，這是正常的，點下去是同一個系統。

如何把ORBIT加到手機桌面(Android)？

全部
  1. 用「Chrome」開啟 app.obarai.com（如果是從 LINE 點連結進來的，建議先複製連結貼到 Chrome 開啟）。

登入不了/忘記密碼怎麼辦？

全部
  1. 如果原本是用 LINE 或 Google 登入：登入不了時不需要重設密碼，直接重新點同一顆按鈕再走一次授權流程即可。
  2. 如果是用信箱＋密碼登入：先確認信箱有沒有打錯（大小寫、有無多打空格）。
  3. 密碼忘記了，點密碼欄位上方的「忘記密碼？」連結。
  4. 輸入登入信箱，點「寄送重設連結」，系統會寄一封重設密碼信到信箱。
  5. 到信箱點連結完成重設。
  6. 都試過還是進不去，請聯繫管理者，或請管理者聯繫 ORBIT 客服 hello@obarai.com。

如何用LINE登入ORBIT？第一次要綁定什麼？

全部
  1. 打開 ORBIT 登入頁，點「使用 LINE 登入」按鈕。
  2. 導去 LINE 授權頁面，第一次使用按「同意並登入」。
  3. 授權完成後系統自動用 LINE 帳號建立/對應一個 ORBIT 登入身分，不需要另外設密碼。
  4. 第一次登入且系統還無法辨識你屬於哪間公司時，會導去「驗證公司身分」頁面，輸入公司統一編號（8碼數字）。
  5. 統編驗證成功後：如果是這間公司第一個登入的人，會直接進入系統；如果公司已經有人建過帳號，會導去「個人資料建檔」頁面，填資料後送出，等主管審核通過才能正式使用。

LINE 登入不需要統一編號以外的額外綁定——不用另外綁手機號碼或加 LINE 官方帳號好友。

第一次使用ORBIT：新人入職設定三步驟

員工

登入 → 驗證公司身分（統一編號）→ 個人資料建檔 → 送出等主管審核

  1. 用公司提供的方式登入（LINE 或 Google 最快）。
  2. 系統辨識不到公司時，在「統一編號」欄輸入公司統編（8碼數字）後按「確認」。
  3. 填寫個人資料：姓名（必填）、部門、職稱、電話、Email、計薪方式（月薪／時薪）、對應的薪資金額，填完點「送出，等候主管審核」。
  4. 送出後系統會建立你的員工資料，但狀態是「待審核」，要等主管在後台核准，才能正式使用打卡、請假等功能。

這個流程只在第一次登入、系統裡找不到對應員工資料時出現，已建檔過的人再次登入會直接進系統。

換新手機了，要重新設定什麼？

全部

新手機：登入 → 加入桌面 → 允許定位權限

  1. 在新手機上用原本的方式登入（帳號本身不用重新申請）。
  2. 把圖示加回新手機桌面。
  3. 第一次在新手機打卡時，會重新跳出「是否允許定位」的詢問，記得按「允許」（iPhone 需選「使用 App 期間」）。
提醒舊手機會自動被登出：ORBIT 是「單一裝置登入」設計——只要在新手機登入成功，舊手機下次操作時就會被強制登出，這是系統本來的設計，不是故障。

畫面跑版/按鈕點不動怎麼辦？

全部
  1. 先確認是不是從手機桌面的 ORBIT 圖示開啟，不是從 LINE 或其他 App 內建瀏覽器點連結進來的。
  2. 把 App 完全關閉（滑掉背景，不是只切到別的畫面）再重新從桌面圖示打開一次。
  3. 還是不行，試著整個重新整理頁面。
  4. 確認手機系統版本、瀏覽器版本不要太舊。
  5. 都試過還是異常，把當下的畫面截圖，附上手機型號、大概的操作步驟，回報管理者。

LINE通知收不到怎麼辦？

全部

目前系統設計如下（跟大部分人想的不一樣，請先看這段）：

  1. 鈴鐺（通知）：那是系統公告／最新消息，不是 LINE 訊息，是站內通知，跟 LINE 無關。
  2. 請假申請送出時：系統會嘗試發一則通知，但對象是「公司負責人本人」，不是承辦的主管、更不是申請人自己，而且要公司完成 LINE 官方帳號串接、負責人本人用 LINE 登入過、以及公司後台「自動通知」設定已開啟，三個條件同時符合才發得出去。
  3. 請假被核准/拒絕時：系統設計是寄「Email」通知申請人，不是 LINE，而且要寄到個人資料裡填的 Email 欄位，同樣要公司開啟「自動通知」才會寄。
目前這是正常現象一般員工收不到 LINE 通知是正常的，請改用畫面上的「請假紀錄」「補打卡申請」列表自己查詢審核狀態。

個人資料填錯了，在哪裡改？

員工（修改須由管理者執行）
目前限制員工自己沒有任何畫面可以修改已經送出的個人資料（姓名、部門、職稱、電話、Email、薪資等）。「個人資料建檔」表單只在第一次登入出現一次，之後找不到「編輯個人資料」的入口——「員工」頁面權限限定在店長／管理者以上。
  1. 發現資料有誤，直接跟主管/店長說明要改哪一項、正確的資料是什麼。
  2. 由主管到後台「員工」頁面，找到你的資料進行編輯。
  3. 涉及薪資的異動，通常需要更高層級的人確認。

為什麼打不了卡，顯示「需要開啟定位服務」？

全部
  1. 最常見原因：從 LINE 等 App 內建瀏覽器直接點連結打卡——這種內建瀏覽器抓不到手機定位。請改從手機桌面的 ORBIT 圖示開啟。
  2. 確認手機系統的「定位服務」總開關是開著的。
  3. 確認瀏覽器/App 本身有拿到定位權限，且第一次跳出詢問時有按「允許」。
  4. 如果之前不小心按過「拒絕」，系統不會再自動跳出詢問，需要手動到手機設定重新開啟。

如果滑動打卡整個沒反應（連錯誤訊息都沒跳出來），不是定位問題，請看「滑動開始上班沒反應怎麼辦」條目。

12

定位權限按到拒絕了怎麼辦？

全部
  1. iPhone：設定 → 隱私權與安全性 → 定位服務 → 找到「Safari網站」→ 選「使用App期間」，並開啟「精確位置」。
  2. Android：設定 → 應用程式 → Chrome → 權限 → 位置 → 選「僅在使用時允許」。
  3. 回到 ORBIT（桌面圖示重新開啟），再打卡一次。

iPhone 特別注意「精確位置」也要打開，只開「大概位置」誤差可能達數百公尺，容易導致打卡範圍判定失敗。

13

人在公司卻顯示不在打卡範圍內？

全部
  1. 系統會顯示明確的錯誤訊息：「您不在店面範圍內（距離XX公尺，允許範圍XX公尺）。如為業務需求，請管理者核發外勤打卡授權。」
  2. 確認手機定位的「精確位置」已開啟——只開一般定位，室內誤差可能達數百公尺。
  3. 走近窗邊或門口再試一次，GPS 在室內深處訊號較弱，容易飄移。
  4. 距離顯示異常大（例如相差好幾公里），代表公司後台設定的座標本身可能有誤，需請管理者確認。
新韻目前設定允許打卡範圍是 100 公尺。系統判定範圍只管「上班」「下班」兩個時間點，午休開始/結束不受地點限制。連上公司 Wi-Fi 不代表定位就會準確，系統是用手機 GPS 座標判斷，不是用 Wi-Fi。

外出跑業務可以在外面打卡嗎？(地理圍欄例外)

員工（核發須由管理者操作）
目前限制系統沒有「員工自己送出外勤申請」的表單，只有管理者可以直接核發授權。
  1. 事先（或當下）用其他管道告知主管，說明今天需要在範圍外打卡的原因。
  2. 由管理者在打卡頁面點「管理者：核發外勤打卡授權」，選擇員工姓名與日期，備註原因，送出後即完成授權。
  3. 授權完成後，被授權的員工當天打卡不會再受地點限制。

這個授權是當天生效、需要每次個別核發的，不是一次設定永久生效。

一天打幾次卡？順序是什麼？

員工

一共固定 4段：上班到 → 滑動「滑動上班打卡」→ 開始午休 →「滑動結束午休」→ 滑動「滑動下班打卡」。

順序系統會強制卡住，跳不過去：如果沒打「午休開始」「午休結束」，直接點下班打卡會被擋下。畫面上方「今日狀態」會顯示你目前在哪個階段，跟著畫面顯示的按鈕打即可。

忘記打卡怎麼辦？

員工

員工考勤 → 補打卡申請 → 新增補打卡

  1. 進入「員工考勤」頁面，切到「補打卡申請」分頁。
  2. 點「新增補打卡」。
  3. 填寫：日期（必填）、上班時間／下班時間（至少填一個）、補打卡原因（必填）。
  4. 點「提交申請」，狀態顯示「待審核」。
  5. 等主管核准，核准後系統會自動把時間寫回當天的打卡紀錄；如果那天完全沒有打卡紀錄，核准後系統會直接補建一筆。
限制目前只能補「上班」「下班」時間，不能補「午休開始」「午休結束」——忘記打的是午休那兩段，需要另外請管理者手動處理。

如何送出補卡申請？

員工
  1. 點「員工考勤」頁面上方的「補打卡申請」分頁。
  2. 點右上角「新增補打卡」按鈕。
  3. 填寫「日期」、「上班時間」與「下班時間」（至少填一個）、「補打卡原因」（必填）。
  4. 確認資料無誤，點「提交申請」。

送出後如果打錯了想改，目前沒有「編輯」功能，只能重新送一筆新的申請。

補卡申請送出後多久會核准？被退回怎麼辦？

員工

系統沒有自動核准機制，也沒有時限規定，完全要等主管手動點「核准」或「拒絕」。核准後，你申請的時間會自動寫入當天的打卡紀錄。

被拒絕怎麼辦畫面不會顯示拒絕原因欄位；如果還是需要補這筆紀錄，目前沒有「重新申請」按鈕，需要直接再送一次新的補打卡申請。

在哪裡看自己的考勤歷史？

員工

員工考勤 → 打卡（近7日）或 歷史紀錄與行事曆（完整列表）

  1. 最近7天的打卡紀錄跟統計，直接在「員工考勤」首頁就看得到。
  2. 要看更早以前的紀錄，點「歷史紀錄與行事曆」。
  3. 「打卡原始紀錄」區塊列出打卡明細，一般員工只看得到自己的資料。

這個頁面不是真正的月曆網格檢視，是「表格列表」形式（一列一天）。

打卡成功怎麼確認？

員工
  1. 滑動打卡成功的瞬間，滑動條會出現打勾的完成圖示，手機會震動一下。
  2. 畫面上方「今日狀態」文字會立刻更新。
  3. 完成「下班打卡」後，畫面會切換成完成畫面，顯示當天扣除午休後的總工時。

如果滑到底卻沒有出現打勾動畫、也沒有跳出任何錯誤訊息：通常代表操作根本沒有送出去，請看「滑動開始上班沒反應」條目排查。

「滑動開始上班」沒反應怎麼辦？

員工
  1. 先確認滑動手勢做對了：需要用手指從最左邊拖到最右邊（拖到底），不是輕點一下。
  2. 確認是從手機桌面的 ORBIT 圖示開啟。
  3. 檢查「選擇員工」下拉選單有沒有出現你自己的名字——選單空的代表帳號權限異常，請截圖回報管理者。
  4. 滑到底後系統會請求定位權限，如果手機當下彈出定位詢問視窗，可能會中斷這次滑動手勢，請重新滑一次。

打錯卡(午休按成下班)怎麼修正？

員工/管理者

系統按鈕是「跟著狀態走」的——還沒打「午休開始」前，畫面只會出現「開始午休」按鈕，不會出現「下班」按鈕，所以理論上不太可能誤把「午休」按成「下班」。

  • 上/下班時間打錯：送「補打卡申請」（自己送出即可）。
  • 午休開始/結束時間打錯：目前的申請表單沒有這兩個欄位，需要請管理者到「歷史紀錄與行事曆」手動編輯。

已經打卡完成的紀錄，員工自己沒有「刪除」或「復原」的按鈕。

23

加班怎麼記？(有無加班申請)

員工
目前限制系統沒有「加班申請」功能——員工完全沒有畫面可以自己登記或申請加班。「加班時數」欄位只能由管理者透過匯入或手動輸入才會出現。

有加班請用口頭或其他管道告知管理者，由管理者透過匯入功能記錄。打卡系統（上下班時間）跟「加班時數」報表是兩個獨立的東西，不會自動連動。

國定假日/補班日出勤怎麼算？

員工

多規格商品怎麼建？（例：CD/USB/數位版）

管理者

重要「規格/尺寸」功能只影響售價，不會各自扣獨立庫存——同一張商品卡片下所有規格共用同一個庫存數字。

提醒「缺貨」是自動判斷，就算沒庫存，只要沒手動按「停用」，商品依然會出現在結帳選單，可能造成「明明沒貨還能被點」。「刪除」跟「停用」不同，刪除後無法恢復，建議暫時下架用「停用」。

進貨驗收怎麼做？

盤點完整流程

領料怎麼操作？

管理者

預測數字（加權營收預測）是怎麼算出來的？可以信嗎？

系統把商機分成 6 個階段，每個階段有一個預設成交機率：新商機 10%、已評估 30%、提案中 50%、議價中 75%、已成交 100%、未成交 0%。越後面的階段代表越接近成交，在預測裡佔的比重也就越高。業務把商機拖到哪個階段，機率就自動帶入該階段的預設值；如果覺得某筆商機的實際把握度跟預設值不同，也可以在新增／編輯商機時手動調整那一筆的 成交機率 %。

這個數字僅供參考，不是精算保證它完全取決於業務有沒有誠實、即時更新商機的階段跟金額——案源進度沒有隨時更新，預測就會失真。本質上這是「業務自己回報的加權估算」，不是根據過去實際成交的歷史數據跑統計模型算出來的。

怎麼測試LINE通知有沒有真的通？

管理者

「整合應用」頁面的LINE官方帳號卡片目前沒有像其他整合項目那樣的「測試並連結」按鈕——LINE走的是自己一套「填Token→存檔」的流程，沒有內建的「傳送測試訊息」功能。以下是目前系統裡實際能拿來驗證的方法，以及各自的限制。

  1. 測試「收訊」方向（顧客傳訊息進來）：用手機把公司的LINE官方帳號加為好友，傳一句話過去，理論上該收到AI客服的自動回覆——但目前這個方法測不出結果，因為Webhook缺少「Channel Secret」欄位（詳見「Webhook是什麼」條目），LINE平台送出的請求一定會被系統擋下，傳過去大概率不會有任何回覆。這不是操作方式錯誤，是系統目前缺欄位的緣故。
  2. 測試「發送」方向（系統推播給顧客）：在「訂位管理」把候位清單裡某筆顧客標記為「已叫號」，理論上會觸發LINE推播——但目前這個方法也測不出真正送達，因為這個動作沒有帶顧客的LINE帳號資訊，畫面本身也沒有地方能取得，請求一定會落到「客人尚未綁定」的分支，只會顯示文字給店員自己看，不會真的送到顧客手機上。
  3. 唯一「按下去、只要Token正確就真的會送出」的測試方式：如果貴公司的「產業別」設定為建案類客戶，「整合應用」頁面會多顯示一個「建案 LINE 推播」欄位，在文字框輸入任意測試文字，按「發送推播」，會推播給LINE官方帳號的全部好友（不是只發給自己）。如果Token正確，畫面會顯示「已推播給全部LINE好友」，自己的手機（如果已加好友）應該會收到這則測試訊息——這是目前唯一能驗證Token本身有沒有設對的方式。因為這是廣播，測試文字要避免寫真實促銷內容，測完記得跟已加好友的人說明這是測試。

「串接LINE官方帳號」視窗按下「儲存設定」出現「✓ 儲存成功」，只代表Token有寫進資料庫，不代表Token本身有效——存檔動作本身不會呼叫LINE API做任何驗證。

目前無法在系統內直接測試Token是否有效如果貴公司的產業別不是建案類，目前完全沒有內建方式可以在系統裡測試LINE Token到底填對了沒有，只能等真的有候位/家長綁定情境發生時，間接觀察有沒有正常運作，或請工程端協助查看伺服器log。貴公司的產業別設定是否屬於建案類，目前待確認。

Webhook是什麼？什麼情況需要設定？

管理者

一般串接LINE，Token是讓ORBIT主動發訊息給LINE用的（例如推播通知）。但反過來，「顧客傳訊息給店家的LINE官方帳號」這件事，LINE平台不會自己知道要把訊息轉去哪裡——需要先告訴LINE「有新訊息時，把資料送到這個網址」，這個「被動接收對方通知」的網址就叫Webhook。

在ORBIT裡，這個網址格式是 {你的網域}/api/webhooks/line/{你的client id}，設定的地方在LINE Developers後台的「Messaging API」設定頁，貼上這個網址並啟用「Use webhook」。

Webhook只有在需要接收LINE傳來的事件時才需要，包含：顧客傳訊息進來、要讓AI客服自動回覆；補教家長要用LINE完成綁定。如果貴公司只需要系統主動推播（例如低庫存警示、候位叫號），理論上不設定Webhook不影響「發送」方向的功能——但因為Webhook網址在「LINE串接設定」視窗是預先顯示好、附一鍵複製按鈕的，系統的預設操作流程是希望每個客戶都設定它。

目前Webhook對所有客戶都會回應403，實際上無法運作LINE官方帳號每次呼叫Webhook都會附一個簽章，系統這端要用「Channel Secret」重新驗算比對，確認請求真的是LINE平台送來的、不是別人偽造的。但目前「LINE串接設定」視窗只有「Channel Access Token」跟「Channel ID」兩個欄位，沒有「Channel Secret」欄位，這個值永遠是空的，Webhook收到請求時一定會回傳403 Forbidden——不管Webhook網址貼得多正確、Token填得多正確都一樣。這不是貴公司專屬問題，是任何客戶都會遇到的現況。受影響的功能：LINE官方帳號AI客服自動回覆完全無法觸發；補教家長LINE綁定完全無法完成（連帶到班/未到班通知也不會發生）。程式碼裡的AI回覆邏輯、綁定碼比對邏輯都已寫得完整，純粹是「進不了門」的問題，待後續補上這個欄位才能真正動起來，目前沒有排定時程。

系統裡還有另一個Webhook，是給n8n這類自動化工具「呼叫回ORBIT」用的技術介接，用另一組共用密鑰驗證，不是LINE的簽章機制。這個Webhook沒有對應的操作畫面，一般不需要操作，這裡列出只是避免跟LINE Webhook搞混。

LINE官方帳號跟ORBIT是什麼關係？

管理者

系統裡跟LINE有關的功能其實是三件互相獨立的事，很容易被當成同一件事，先分清楚：

  1. LINE官方帳號（OA）：貴公司自己申請、自己擁有的帳號（客人在LINE上加好友的那個帳號），跟ORBIT完全無關的資產——就算哪天不用ORBIT了，這個帳號還是貴公司的，好友名單也還在，ORBIT不會、也不能「取代」這個帳號。
  2. ORBIT串接這個OA帳號：把OA帳號後台的「Channel Access Token」貼到ORBIT的「整合應用」頁面，等於授權ORBIT可以用貴公司的名義透過這個OA帳號發訊息、（理論上）收訊息。概念上很像把LINE官方帳號的「遙控器」交給ORBIT代操作，OA帳號本身還是貴公司的，密碼／後台管理權都還在貴公司手上，ORBIT只是拿到一組可以呼叫LINE API的Token。
  3. 員工／老闆個人用LINE登入ORBIT：完全不同的另一件事，是「人」登入「ORBIT系統」的方式，跟前面兩點的OA帳號無關。

貴公司的客人在LINE上看到、加好友的，永遠是貴公司自己的LINE官方帳號，不會看到任何「ORBIT」字樣，客人感覺不到背後是ORBIT在運作。設定完Token之後，理論上系統可以在特定情境（結帳完成、候位叫號等）自動代替貴公司用這個OA帳號發訊息給客人——但目前實際上能自動送達的情境非常少，多數還卡在缺功能或缺欄位的階段，不是設定好Token就等於全部自動化都會動起來，這點請務必先理解清楚，避免預期落差。

如果OA帳號被停用、或Token重新產生過期，ORBIT這邊的推播／自動回覆功能會跟著失效，需要重新去OA後台複製新的Token貼回ORBIT——這不是ORBIT系統故障，是常見的憑證過期情境，發生時重新設定即可。

目前架構是一個公司對應一組LINE官方帳號如果貴公司未來想用「客服帳號」「活動帳號」分開經營，或總店＋分店各自一個OA帳號，目前架構不支援同時串接多個，需要另外規劃，屬於待確認/待規劃事項。

客戶問「這份文件怎麼證明是真的」，要怎麼解釋？

管理者（對客戶說明用，操作本身任何登入者皆可觸發）

每張DOCS單據每次建立或修改，系統都會把當下的完整內容（單據資料+品項明細）算出一組獨一無二的SHA-256雜湊值，存進資料庫，並在產生PDF時把這組雜湊值編進PDF上的QR碼裡。只要文件內容有任何一個字被改過（不管是系統內編輯，還是有人事後竄改PDF檔案本身），重新計算出來的雜湊值就會跟原本存的對不上，驗證就會失敗。

客戶怎麼驗證：

  1. 客戶用手機掃描PDF文件上印的QR碼。
  2. 會導到一個不需要登入的公開驗證頁，任何人都能查，不用有ERP.POS帳號。
  3. 驗證通過會顯示「此文件驗證通過」，並列出單據編號、版本（含是否為最新版）、建立時間、是否已簽署電子簽章；驗證失敗會顯示「此文件內容與系統紀錄不符，可能已遭竄改或非ORBIT系統產出的文件」。

跟客戶解釋可以說：「這份文件上有一個QR碼，掃了可以直接連到我們系統確認這份文件是不是我們開的正本、內容有沒有被改過。如果被動過手腳，掃出來會顯示驗證失敗，不需要打電話回來核對，掃碼就能自己查。」

驗證頁不會顯示簽名長相驗證頁只顯示「有沒有簽署」，不會顯示簽署人是誰、簽名長什麼樣，避免公開頁洩漏簽名圖檔本身。舊版本的單據（例如已經改成v2的v1）拿出來掃仍然驗證得過，但頁面會標示「非最新版本」。

單據的草稿/送出/核准/作廢是怎麼流轉的？

全部（送出／完成：員工可操作；核准／作廢：需店長以上）

DOCS的10種單據共用同一套狀態流程：

  1. 草稿：剛建立、還沒送出，可自由編輯內容。
  2. 待處理：已送出等待核准，仍可編輯內容。
  3. 已核准：已核准，不能再編輯內容。
  4. 已完成：流程走完，不能再編輯。
  5. 已作廢：作廢，不能再變更（終點）。
  6. 已封存：封存，不能再變更（終點）。

流程：草稿 →（按送出）→ 待處理 →（按核准）→ 已核准 →（按完成）→ 已完成。任何非終止狀態下都能按作廢（草稿/待處理/已核准/已完成都能作廢），按下會跳出提示要求輸入作廢原因，沒填原因無法送出。

每個動作需要的角色：送出與完成只要收銀員以上就能按；核准與作廢要店長以上。

不是嚴格線性流程系統技術上允許同一張單直接從「草稿」跳到「作廢」，不強制一定要照「送出→核准→完成」的順序才能作廢，只要不是已作廢/已封存狀態，隨時都能作廢。一旦進入「已作廢」或「已封存」，就不能再做任何狀態變更。單據編號不管作廢與否都不會被重複使用或回收。

單據可以刪除嗎？

管理者（作廢動作需店長以上）

結論：不能刪除，只能作廢。DOCS的10種單據在系統設計上完全不提供刪除功能，這是刻意的硬性限制：前端沒有任何「刪除」按鈕，後端API也沒有實作刪除方法，資料庫層級再掛一道觸發器擋住刪除動作，就算工程師想直接操作資料庫刪除都會被擋下並丟出錯誤。

要「移除」一張不要的單據，唯一的方式是作廢（狀態改成「已作廢」，見129號條目），作廢後：

  1. 單據本身不會消失，仍然留在列表裡（狀態顯示「已作廢」）。
  2. 單據編號永久保留、不會被其他新單據重複使用。
  3. 作廢時必填的「作廢原因」會被記錄下來，之後在詳情頁最上方會顯示「作廢原因：xxx」。
  4. 這次作廢動作本身也會產生一筆新的版本紀錄，完整保留「誰在什麼時候把它作廢、為什麼」。

版本歷史紀錄同樣不能刪除或修改——每一筆版本紀錄都是只能新增、不能修改或刪除，確保稽核軌跡完整。

手滑建錯的單也只能作廢如果是純粹手滑建錯一張單、內容完全不需要，也只能作廢，不能刪掉讓它徹底消失，列表裡會一直看得到這張「已作廢」的單據。

  4. 現場人員（waiter）
  5. 工務（supervisor）

目前尚未確認的需求公告目前只能依角色（管理員/主管/一般員工/現場人員/工務）篩選發送對象，不能依部門發送。這是否符合新韻的實際需求還未確認；如果需要「發給特定部門」的公告功能（不是一個一個點名的私訊），目前系統沒有這個功能，需要另外評估開發。

沒有長期例外選項系統沒有「這個人以後都不用檢查範圍」的設定；授權日期選錯，員工當天仍然打不了卡，建議核發後請員工當場確認能不能打卡成功。

考勤報表上的「早退」是怎麼算出來的？

管理者

先講結論：目前系統沒有「早退（有待核准假單）」這種即時複合判定機制，「早退」本身也不是系統即時運算出來的狀態。

  1. 打卡只會在打上班卡時判斷一次「遲到」（超過09:30算遲到），除此之外，系統沒有任何排程或觸發器會在下班打卡、或一天結束後，回頭把某筆紀錄標記為「早退」或「缺勤」。

  3. 假單核准與早退狀態之間沒有任何連動：不存在「核准假單後系統自動把早退清掉」這種自動修正機制，因為根本沒有「早退」這個即時判定在跑。

目前不支援自動判定「下班打卡自動比對排班判早退」「排程掃描未打卡標記缺勤」「假單核准後回溯修正當天出勤狀態」這三塊邏輯目前完全空白，是否要排入開發規劃尚待確認。

用LINE/Google/Email分別登入，算不算同一個人？

全部

不算，會被系統當成兩個不同的人。三種登入方式（LINE／Google／Email＋密碼）各自獨立建立帳號，系統不會自動比對信箱或電話去合併。同一個人如果先用LINE登入建了帳號、之後又改用Google登入，會產生第二個帳號，兩邊的資料互不相通。

  1. 第一次登入用哪種方式，以後就固定用那一種——這是最重要的一條。

管理者

操作路徑：員工頁，依序完成以下確認與停用。
